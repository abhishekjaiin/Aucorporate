## Claims That Could Not Be Verified — MUST FIX

| Claim | Issue |
|---|---|
| **"Registration runs through the non-resident taxable person route, using Form GST REG-09"** | **Factually wrong, not just unsourced.** Multiple independent sources (ClearTax, TaxTMI, SAG Infotech, GST Gyaan, IndiaFilings, and gst.gov.in's own tutorial page titled "Non-Resident Online Services Provider") consistently identify **Form GST REG-10**, filed under **CGST Rule 14**, as the correct form for a person supplying OIDAR services from outside India. Form **GST REG-09** is a different form, for the general "Non-Resident Taxable Person" category under CGST Rule 13 — someone who occasionally undertakes physical taxable transactions in India (e.g. a trade-fair exhibitor) without a fixed place of business, a materially different fact pattern from a foreign OIDAR/digital-services supplier with zero physical presence. **Must be corrected to Form GST REG-10 throughout the page** (header, body, any FAQ references) before publication — this is the highest-priority correction on the page, since it sits in a section that exists specifically to tell readers which form to file. |
| **"SAC Code 9983"** for OIDAR supplies | Sources conflict. Several vendor blogs casually apply "9983" (the broad heading for "Other professional, technical and business services") to OIDAR generically. More granular classification sources point to heading 9984, specifically group 99843 / code 998439 ("Other on-line contents n.e.c."), as the more precise classification — with at least one source associating a different rate (5%) with 998439, itself unresolved (may be an error, or a narrower carve-out like e-books). No primary CBIC rate-schedule source definitively resolves which code is correct for OIDAR invoicing specifically. **Recommend confirmation by a GST professional against the actual rate notification (Notification No. 11/2017-Central Tax (Rate), as amended) before the page states a specific SAC code on customer-facing invoicing guidance.** |
| **"Intensifying DGGI enforcement via payment-gateway and card-network data cross-referencing"** (the specific mechanism) | The general enforcement-intensification trend is real and well-sourced (see Verified table). But the specific mechanism named — "payment-gateway and card-network data" — does not match what the sourced 2024 DGGI proposal actually describes: RBI forex-transaction data (Purpose Code Group 8), the "KODEX" platform, foreign-government information-sharing, and website-blocking. No source describes payment-gateway/card-network data specifically as a named DGGI mechanism. **Adopt the SEO editor's fallback: drop the "payment-gateway/card-network data" detail**, replace with a general, defensible, "reported" (not asserted) statement about DGGI coordinating with RBI and other agencies to identify offshore suppliers billing Indian customers without registration. |

## Regulatory Currency Check

- **Equalisation levy framing is current and correctly past-tense.** Both the 2% (Aug 2024) and 6% (April 2025) levies are confirmed withdrawn; nothing in the draft describes them as live.
- **The October 2023 OIDAR amendment is correctly treated as the current, governing definition** — the draft does not describe the pre-amendment "minimal human intervention" test as still operative.
- **Nuance worth tightening, not a factual error**: the substantive amendment was made by Section 160 of the Finance Act, 2023 (amending IGST Act §2(16)/(17)); Notification No. 28/2023-Central Tax (31 July 2023) is the *commencement* notification bringing it into force from 1 October 2023, not the source of the definitional text itself. The draft currently doesn't cite a notification number at all (the safer choice, per the writer's own note) — if one is added later, phrase it as "brought into force via Notification No. 28/2023-Central Tax," not as the amendment's source.
- **The GST REG-09/REG-10 error is a live regulatory-currency risk in itself** — REG-09 and REG-10 are two different, currently-valid forms for two different registrant categories; using the wrong one is directly misleading about which form a reader should file. See Must Fix table.
- No sign of any currently-superseded rule silently treated as live elsewhere on the page.
